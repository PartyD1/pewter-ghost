# Decisions

- 2026-10-07 (level, G-02/G-08): `LevelModel.subscribe` delivers `LevelChangeEx`, which extends the contract's `LevelChange` with optional `entitiesUpdated` (enemies whose derived patrol span changed), `start`, `goal` (null = cleared) and `revision`. contracts.ts is unchanged; anything typed as `LevelChange` still works. Renderers should process `entitiesRemoved` before `entitiesAdded` (an id can appear in both when it was removed and re-added in one step).
- 2026-10-07 (level): model invariants: at most one entity per cell, and no entity inside a solid tile (painting a tile removes the entity there; placing an entity clears the tile). Erase removes entities by default. Enemy `patrol` is derived from the grid (`computePatrol`) and recomputed after every change; save files store it but loaders recompute it.
- 2026-10-07 (level): save v2 stores `grid`/`authors` as one string per row (digits), for readable diffs. v1 import maps tiles 1,4,5,6,7 to terrain and 2/3/8/9 plus the `enemies` list (pixel spawns / 16) to entities, all author PERSON; unsupported "Dynamic" enemies and bad entries are skipped with warnings instead of failing the load. v1 start = old spawn pixel (100,100) -> tile (6,6). New levels start at (2,14).
- 2026-10-07 (level): share code = `pg1.<d|r>.<base64url>`; d = deflate-raw (CompressionStream), r = PackBits RLE; auto picks the shorter. Provenance and entity ids are not shared (ids become e1..eN); a FNV-1a checksum detects typos.
- 2026-10-07 (proxy, G-09): `Recording` gains optional `temperature`, `samples` and `raw` (raw model text per sample, written only when a sample failed to parse) so prompt work can see garbage answers. Additive only.
- 2026-10-07 (proxy, G-09): /fill answers HTTP 200 with `answer: null` and `error` set when the upstream times out or fails, so the client always receives `requestHash` for its fill.call event; 4xx is reserved for client mistakes (401 token, 403 condition/session mismatch, 400 body, 413 size, 429 rate limit with Retry-After). /fill is refused (403) for tokens whose condition is not `llm`. Superseded client calls are not cancelled upstream: the proxy finishes and records them.
- 2026-10-07 (proxy, G-33): a token maps to `{sessionId, condition, overrides}`. /fill and /log accept the token's sessionId or `<sessionId>.<suffix>`; the open dev token (`PROXY_OPEN=1`, token `dev`) gets a fresh `dev.<stamp>` id from every GET /session. /log also accepts `?token=` because `navigator.sendBeacon` cannot send headers. The client sanitises overrides against `DEFAULT_CONFIG` (proxyUrl is never overridable) and always sets `filler = condition`.
- 2026-10-07 (research, G-18): `requestHash` = sha256 hex of canonical JSON (sorted keys, no whitespace, undefined dropped) of the FillRequest, implemented once in `apps/editor/src/research/hash.ts` and used by both proxy and client.
- 2026-10-07 (suggest, G-17/G-24): config.ts gained manager fields (no contract change): `cooldownMarginTiles` 1, `newStructureTiles` 6, `ghostTimeoutMs` 30000 (outcome "timeout"; 0 = never), `requestWindowMs` 3000 (Ctrl+Space with nothing held makes the next suggestion show as "requested"), `dismissOnDrawElsewhere` true, and per-session threshold adaptation `adaptThresholds` true / `adaptStep` 0.05 / `adaptMin` 0.5 / `adaptMax` 0.95 / `adaptRun` 2. Flat fields so `applyOverrides` (shallow) can override each one.
- 2026-10-07 (suggest): SuggestionManager is one slot: a newer offer drops a held one ("superseded") or ends a shown one ("replaced") at once, even if the newer one must wait for a pause. Exceptions: a patrol fix shows immediately ("patrol") and, while shown, can only be replaced by another patrol fix or a requested suggestion (others dropped "blocked"); an identical cell set never replaces the shown ghost ("duplicate"). Patrol fixes are exempt from the dismiss-streak lock but not from cool-downs or fix grace. Requests bypass cool-down, streak, mute and per-problem rate, never fix grace.
- 2026-10-07 (suggest): paint-on-ghost: a placement that puts exactly the proposed thing on a ghost cell (same tile; erase on a removal; same entity kind) accepts that cell and the ghost stays; any end of a ghost with ≥1 such cell (other than Tab) is reported as "partial" with `acceptedCells` = that count (all cells painted by hand ends "partial" with the total). Drawing on a held (not yet shown) suggestion's cells drops it as "stale". Fix problem key = normalised label + "@x,y" of the anchor; a drawn-over fix is muted until a later stroke (or undo/redo via `onCellsChanged`) changes one of its cells. Dismissals for streak/cool-down/thresholds = "esc" and "drawn-over"; "replaced"/"timeout"/"pending" are neutral.
- 2026-10-07 (fill, G-12/G-13): in a FillRequest only `origin` (and `size`) are in level coordinates; `recent`, `frontier`, `blockedAt` and every coordinate inside `grid`/`summary` are WINDOW-relative, like the model's answer. Grid glyphs: person terrain upper case (G grass, D dirt, B block, H half, Q ?-block), accepted-ghost terrain the same letter lower case, `o` coin, `*` fruit, `S` slime, `U` ultraslime, `~` patrol span, `F` flag, `!` sign, `@` start. Window: centred on the last stroke, shifted toward the frontier by half the distance (max a quarter window); vertical drawing puts the frontier ~40% from the top; patrol puts blockedAt ~40% from the left. `requestHash` (fill/hash.ts) equals research/hash.hashRequest, with a pure-JS SHA-256 fallback when SubtleCrypto is missing. No contract changes.
- 2026-10-07 (ghost, G-11/G-19): the Play-mode route key is **R** ("route"; P already stops Play). It shows the stored agent route of an accepted ghost covering the knight's column (or within 12 tiles), else `GhostSessionOptions.routeProvider`. Ghost keys are DOM listeners on window in the capture phase: Tab/Shift+Tab are swallowed only while a ghost is shown (focus never moves then; normal Tab otherwise), Esc dismisses only in edit mode with a ghost shown or a Ctrl+Space pending. The ghost session writes `ghost.show`/`ghost.end` through `api.log` and supplies the save-file history via `setHistoryProvider`. `main.ts` should `import "./ghost/boot"` to start it (the ghost e2e injects that module until it does). No contract changes.
- 2026-10-07 (fill, G-14): prompt v1 layout: `system` = prompts/fill.v1.md (knight numbers and the reach table filled in from @jump-tables) + the static brief + six few-shots, the same for every request so the upstream can cache it. `user` = the request (grid, recent, frontier, knight, mode, blockedAt, previous failure, measured, summary, last ghosts, then `req.brief`). `PROMPT_VERSION` = `fill.v1-<first 8 hex of sha256(system)>`, so any change to the prompt, brief, few-shots or tables changes the version. The answer key order is act, kind, label, levelGuess, adds, removes, entities, confidence (responseSchema `propertyOrdering`): the model names the idea before it draws, and states confidence last. The previous-failure line tells the model the reason is in LEVEL coordinates and gives the origin to subtract, because validator reasons use level coordinates.
- 2026-10-07 (fill, G-14): `parseModelAnswer` is strict. `act` must be a boolean. With act=true, kind, label and confidence are required, and adds, removes and entities default to []. With act=false the answer is normalised to empty arrays and confidence 0. Enum values are matched case-insensitively, with "-" or " " read as "_". Any other out-of-enum tile, entity or kind rejects the whole answer (null, a schema miss). Coordinates must be integers within ±1000; window bounds are left to fill/answer.ts. Confidence in [-0.05, 1.05] is clamped to [0, 1]; anything else (85, -1, "0.8") rejects, because a model answering on another scale cannot rank its suggestions. More than 200 cells rejects. Unknown keys are ignored. The parser also accepts the raw text and strips a ```json fence.
- 2026-10-07 (fill, G-21): the static brief (prompts/brief/*.md) lives in the system prompt. `FillRequest.brief` carries only the dynamic part from `buildBrief()`: measures of the last two 24-column screens up to the frontier, detected patterns, the model's last levelGuess, last ghosts with outcomes, the variety rule, and optional G-31 examples. `briefVersion` = `BRIEF_VERSION` = `brief.v1-<hash of static text + dynamic format>`. Budgets (est. chars/4): static ≤ 2200, dynamic ≤ 450, examples ≤ 400. `measureRequestWindow` (fill/brief.ts) is the MeasureFn to pass to buildFillRequest so `measured` is real.
- 2026-10-07 (fill): prompt sources are bundled into prompts/bundle.ts, a generated TS module, so Vite, tsx, the Worker and Vitest load the same text with no fs or `?raw` loader. Regenerate with `npx tsx prompts/fewshot/make.ts` (few-shots + bundle) or `npx tsx prompts/build.ts`. fill/prompt.test.ts fails when either is stale. Reference chunks (G-31) are re-drawn in the window's glyphs, because @measure's ASCII uses a different alphabet (# d = ? c ...) and mixing two alphabets in one prompt invites errors.
- 2026-10-07 (fill, G-14/G-27): LLMFiller never rejects. On abort, timeout (config.callTimeoutMs), HTTP or network errors it resolves null, and `fillDetailed` returns a FillResult with the error for the fill.call event (`fillCallEvent`). The logprob confidence is exp(mean token logprob); when the proxy sends none it falls back to stated (`confidenceFallback`). twoSample asks for samples=2, with agreement = |shared typed cells| / |union| (same cell with a different tile is not shared). `varietyTwoSample` (G-25 flag) also asks for 2 samples and keeps the extend whose label is least like the recent ghost labels. FillScheduler marks an aborted call `superseded` and nulls its suggestion even if the filler ignored the signal.
- 2026-10-07 (fill, live smoke): on gemini-3.7-flash with thinking off, the three fixture requests got 15 answers over three runs. All 15 parsed and 14 passed the validator. The one failure was coins laid flat on a platform, on fill.v1-a9effa90. That led to a coin rule in "Rules for the cells", and all 6 answers on fill.v1-b9e8fd87 passed. Findings: (1) with default thinking a call takes 16-20 s; with `PROXY_THINKING_BUDGET=0` it takes about 2.0-2.5 s. (2) Latency is mostly fixed API overhead: a 9-token prompt took 1.6-2.0 s and the full ~8k-token system prompt took 1.3-1.4 s. Shrinking the prompt will not reach the 900 ms timeout, so model and endpoint choice (G-28) is the lever. (3) This model rejects `responseLogprobs` (the upstream drops it), so G-27 has stated vs twoSample only. (4) The real prompt is ~9k tokens; estimateTokens (chars/4) undercounts ASCII grids by about 20%.
- 2026-10-07 (integrate, G-17/G-23/G-33): the loop lives in `apps/editor/src/session.ts`. `FillLoop` has no Phaser and runs in Node tests. `PewterApp` is the boot glue that `main.ts` creates with the model. Every person placement schedules a speculative fill, and placements within `config.fillDebounceMs` (new field, default 40) are coalesced so a brush drag does not make one call per cell. Newest wins: a newer trip aborts the call in flight (FillScheduler) and also the verification still running for an older answer. Each aborted call is logged as `fill.call` with `superseded: true` and error "superseded". Only `verifyWithSendBack` / `verifyPatrolFix` output reaches `GhostSession.offer`, with `requestedAt` = when the request was built.
- 2026-10-07 (integrate): `fill.call` is one event per model call. The first call carries the verdict of attempt 1 (`verdictStage` "ok" or the failing stage, plus `reason`) and `sendBack`. The send-back call is its own event with `sendBack: true` and its own requestHash. The local ≤3-tile patrol repair is not a model call, so it writes no fill.call; it appears as `ghost.show` with filler "algo" when shown. The event logged first is always `session`. Events from before the session resolves are buffered by `SessionLog` and written after it.
- 2026-10-07 (integrate, G-33): config precedence is DEFAULT_CONFIG ← URL (`?filler=`, `?proxy=`, `?callTimeoutMs=`) ← `GET /session` overrides. The overrides apply only when the proxy actually answered; the local fallback's condition is ignored. The `llm` filler is registered only with a session token. Without one the session runs as "none", because the proxy would refuse every call. "algo" (G-34) is not built, so an algo token runs as "none" for now. "none" means no calls, no patrol, no ghost UI.
- 2026-10-07 (integrate, G-23): patrol runs from the start to the person's frontier. That is the stream's frontier, else the rightmost person- or ghost-authored column, else the start column. It is never the starter template's goal platform, so an untouched new level is not "blocked". Answers to a patrol request are verified as `kind: "fix"` (the manager's patrol-interrupt rule requires kind fix + mode patrol). Patrol and fills pause during Play.
- 2026-10-07 (integrate, fix in verify/pipeline.ts): `verifyOnce` now keeps the validator's pattern `tags` on the final (playability) verdict, so `lastGhosts[].patterns` can name patterns (G-25). This is additive.
- 2026-10-07 (integrate, SECURITY): reading `import.meta.env` as a whole object makes Vite inline every `VITE_*` variable into the bundle, `VITE_LLM_API_KEY` included. An early `session.ts` did exactly that, and the local build contained the key until it was fixed. App code may only read `import.meta.env.VITE_COMMIT` style static properties; `session.test.ts` scans apps/ and packages/ for any other use. CI builds with a fake canary key in `VITE_LLM_API_KEY` and fails if it, or any `AIza` pattern, appears in `dist/`.
- 2026-10-07 (integrate, e2e): the ghost layer check (`ghostCheck.cjs`) now loads `?filler=stub` and calls `window.__pewter.app.loop.setSuspended(true)`. The ghost UI is on, but only the script's hand-made suggestions reach the manager. The whole-loop check is `apps/editor/src/__e2e__/loopCheck.cjs` (stub, or `--llm` against a running proxy).
- 2026-10-08 (fill, timeout): `callTimeoutMs` default is 6000 (was 900 in the plan, then 3500). Measured on gemini-3.7-flash with thinking off: 2.0 s p50, 2.9 s p90, 3.6 s p98, 11.4 s max over 52 calls (eval/runs/baseline.json), plus a live staircase call that took 5.2 s and was right. 3500 threw that answer away. 6000 keeps every measured answer except the 11 s outlier. The timeout now only bounds a hung call: freshness is reconciliation's job (below). It stays under the new `maxAnswerAgeMs` (8000), so an answer that beats the timeout is still young enough to be shown. The model stays gemini-3.7-flash: smaller models scored 65-79% coordinate accuracy in the eval, against 100%.
- 2026-10-08 (fill, speculation with reconciliation; replaces "newest wins" in the 2026-10-07 G-17 line): a new placement no longer aborts the calls in flight. `FillScheduler` keeps up to `config.maxInFlight` (new, default 3) calls running side by side and aborts only the OLDEST when one more would exceed it. Every answer that arrives goes through `fill/reconcile.ts` against the level as it is NOW: dropped when the request is older than `config.maxAnswerAgeMs` (new, default 8000), when the person drew or erased something else on its cells since the request, when they already drew all of it, or when an answer to a NEWER request overlapping its area was already offered (shown or held); cells the person has since drawn exactly as proposed are trimmed off. The rest is verified on the current level and the age / newer-offer check runs again just before `GhostSession.offer`. Measured case this fixes: a 3-step staircase at 400 ms per tile, where the 2nd call's correct 2.1 s answer used to be thrown away. Contract: no new field. `fill.call` keeps `superseded: true` + error "superseded" for every call whose answer did not reach the manager, and its existing optional `reason` says why: "stale: too old", "stale: cells drawn", "stale: all cells drawn", "stale: newer shown", "aborted: over maxInFlight" or "cancelled" (Play, load, filler switch). A call dropped after verification ("stale: newer shown" / "stale: too old") keeps its `verdictStage`. For plain fillers (stub, algo), which return no ModelAnswer, `act` is now true when they returned a suggestion (was null).
- 2026-10-08 (fill, reconciliation: two more drop reasons, after review of the speculative-calls change): a late answer is now also dropped when (a) the person has placed since its request and their LATEST placement is outside the answer's box grown by `config.newStructureTiles` -> `fill.call` reason "stale: area left" (the plan's "if they are still drawing the same pattern, apply"; without it a ghost shown behind the person was ended "drawn-over" by their next placement via dismissOnDrawElsewhere and counted as a dismissal they never made: streak, threshold and cool-down); no placement since the request keeps the answer; and (b) a NEWER request whose window covers the answer was answered act:false (a plain decline, not an error or timeout; not patrol) -> "stale: newer declined": newest wins, a decline included. Both are checked on arrival and again just before the offer. A trip that settles after `FillLoop.dispose()` writes no `fill.call` and reports no outcome; a trip cancelled by Play / load / `cancel()` still writes its "cancelled" `fill.call` (intended: the call was made and the log stays complete).
- 2026-10-08 (look, final regression): the editor follows the Pewter Platformer look (page frame, canvas, right panel, bottom toolbar, glass, type and colours copied from the old UIScene.ts / chatbox.css) with the plan's removals: no chat, no tabs, no selection boxes; the ghost is on the canvas and its one status line and switch are the panel's last group; Help replaces the Controls tab (docs/look/README.md). Speculative answers are reconciled against the level as it is now instead of cancelled by the next placement (see the 2026-10-08 fill lines above). tsc clean, Vitest 1354/1354, build with no key pattern in dist/, Playwright 30/30 on two consecutive runs.
- 2026-10-22 (editor, markers): the Start pennant now shows in edit view wherever the start is, the default spot included, so a new level opens with both a visible start and the goal flag (the starter level's flag at column w - 4 is unchanged). It was hidden at DEFAULT_START to match the old editor.
- 2026-10-22 (contracts, checkpoints): new entity kind `checkpoint`, appended LAST to ENTITY_KINDS so existing share codes (which store the kind's index) still decode. In Play, touching a checkpoint makes it the respawn point; after a death the knight respawns on the most recently touched checkpoint, else the start; activation lasts the Play session (pure logic in editor/checkpoints.ts). Enemies and collectables still reset on respawn. It stands on ground like a flag (validator rule), any number per level, drawn from the Kenney sheet's unused second flag frame [12, 5] recoloured blue (composite frame 14). Window glyph `C` (@measure `C`). No new log event or PlayResult field.
- 2026-10-22 (fill, checkpoints in the prompt): the model may now place `checkpoint` entities. Added to ENTITY_KIND_NAMES (responseSchema enum and parser), the window LEGEND (`C checkpoint`), fill.v1.md (glyph line and the entity rule: checkpoints stand on a floor) and brief/placement.md (on a rest after a hard stretch, at most one every two screens, not on a landing tile or beside an enemy). PROMPT_VERSION and BRIEF_VERSION change; bundle, few-shots and snapshots regenerated (few-shot window text omits the legend, so the few-shot JSON is unchanged).
- 2026-10-22 (editor, Play rendering): in Play the follow camera's scroll is snapped after each follow update (camera.ts snapFollow, cameraMath.snapScroll) so the world origin lands on a whole screen pixel, and the camera's renderRoundPixels is forced on so sprites (knight, enemies, pickups) draw at whole screen pixels. The lerped startFollow at zoom 2.25 drew tiles at fractional positions; the Canvas tilemap renderer ignores roundPixels and anti-aliases tile edges, which showed as lines between backdrop tiles and a blurry ground and knight. Phaser's own roundPixels floors to whole world pixels (fractional on screen at 2.25) and only rounds sprites at integer zoom. Measured: a row of the sky band had 26 off-colour columns unsnapped, 0 snapped. Edit mode is unchanged.
- 2026-10-22 (physics, side walls): the level's left and right edges are walls in Play and for the playtest agent (before, the knight could run off either side and die; physsim grid.ts said "out-of-bounds = empty"). Play: configurePlayerSprite sets collideWorldBounds, and PlayController.start sets the world bounds to the level with setBoundsCollision(true, true, false, false), so the top and bottom stay open (jump above the level, fall out of the bottom). physsim: frame() ports Body.checkWorldBounds for the sides (after the cached deltas, as in Body.update; bounce 0), and makeSolid treats columns outside the level as solid (rows above and below stay empty). Level.solid / tile faces still mirror the Phaser layer, where outside cells are empty. The parity test now runs Phaser's own Body.prototype.checkWorldBounds in its engine harness, with a new side-wall case; disabling the sim's clamp fails it and three older parity cases.
- 2026-10-27 (suggest, timing policies; G-36 and Mozannar et al. 2023 "When to Show a Suggestion?", arXiv 2306.04930): new flat config `timing: "llm" | "cdhf" | "jev"` (default "llm", URL `?timing=`, token override) picks who decides when a verified ghost appears; the filler, verifier, manager rules and requests are the same under all three. "llm" is the behaviour before this change (ConfidenceTimer: the model's act + stated confidence). "cdhf" is the paper's two-stage cascade with logistic regressions over activity + ghost features (suggest/timing/features.ts, model.ts): stage 1 `TimingPolicy.gate` skips an auto/tidy call when P(accept | context) < `cdhfGateBelow` (0.12) and its entropy < `cdhfGateEntropy` (0.55 bits); stage 2 `CdhfTimer` shows a held ghost once P(accept | context, ghost) >= `cdhfShowAbove` (0.3), else holds it ("request"); re-asked every tick, so a ghost hidden mid-drag shows at the pause where it becomes likely (the paper decides once; here that makes "whether" into "when"). Deviation: a confident stage-1 accept still goes through stage 2. Weights: hand-set PRIOR_WEIGHTS until `eval timing --train` fits `cdhfWeights` on logs. "jev" replaces the throwing JevTimer placeholder: `JevPoller` posts the auto window, recent placements, activity and the held ghost to the proxy's new `POST /when` every `jevIntervalMs` (1500), the cheap model (`JEV_MODEL`, else the fill model) answers `{suggest, p, why}`, `JevTimer` shows while the latest verdict is "suggest" and younger than `jevMaxAgeMs`; "suggest" with nothing held asks the loop for one auto call (`FillLoop.nudge`). `new JevTimer()` with no verdict source still throws. Contracts: new LogEvent `timing` (stage "show" for every shown ghost under every policy, with features and the CDHF p, so "llm" sessions are training data; "gate" for skipped calls; "jev" for every verdict or failed poll), JevRequest / JevVerdict / ProxyWhenBody / ProxyWhenResponse; no existing field changed. Proxy records /when exchanges to `jev/<sessionId>.jsonl`. Prompt bundle and PROMPT_VERSION unchanged (the Jev prompt lives in suggest/timing/jevPrompt.ts with its own `jev.v1-` version).
- 2026-10-27 (fill, Markov filler): new filler `markov` (fill/MarkovFiller.ts; `?filler=markov`, token condition "markov"), a constrained multi-dimensional Markov chain after Snodgrass & Ontañón: P(tile | left, below, below-left) per level row with backoff to 4 height bands, trained on the bundled reference sections (weight 1) plus the request window up to the frontier (weight 6, so the person's palette, steps and gap widths win); extend only, sampled column by column bottom-up with drawn cells fixed; lone sampled tiles cleared; the rule check runs from the frontier to the last new column and only the columns past `blockedAt` are resampled (up to 6 times, 4 candidates); a second "skin" layer re-picks each new solid cell's tile from (solid above?, solid below?, left tile) so tops get the surface tile. The first passing sample is offered (the likeliest of several was always a flat run); confidence is its structure-cell likelihood mapped to 0.2..0.6. Patrol, tidy and finish decline; no entities. 3-15 ms per call on a 24x12 window. Registered in `buildRegistry` always (no calls); `FillerName`, the log schema's filler enum, `GhostConfig.filler`, proxy/client CONDITIONS and the strip's hidden words gain "markov". The offline suite does not run non-LLM fillers yet (neither does it run algo).
- 2026-10-27 (proxy, Jev-like model for /when): `/when` picks its own provider: `JEV_PROVIDER` (gemini | openrouter | bayleaf | local) and `JEV_MODEL`; `JEV_PROVIDER=openrouter` alone uses `liquid/lfm-2.5-2.6b:free` (Liquid LFM2.5 2.6B, compact open weights, structured output, logprobs; free tier 20 requests/min, 50/day or 1000/day after $10 of credits); `local` is any OpenAI-compatible server at `JEV_BASE_URL` (default Ollama's http://localhost:11434/v1) for unlimited polling. TypeSafe's real Jev (typed decisions, Eden AI `POST /v3/alpha/decisions`, model `typesafe/jev-latest`) needs an Eden key and is not wired. `jevIntervalMs` default 1500 -> 3000 and `jevMaxAgeMs` 3500 -> 5000, to stay under the free tier's 20/min. `/when` now serves every condition but "none" (`whenConditions`), since timing is independent of the filler.
